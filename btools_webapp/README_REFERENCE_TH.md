# รุ่นวิเคราะห์โครงสร้างด้วยข้อความอ้างอิง

อัปเดตโค้ดในเครื่องวันที่ 9 ตุลาคม 2026 ยังไม่ได้ deploy หรือแก้การตั้งค่าออนไลน์ รุ่นนี้ปรับเฉพาะการอ่านต้นฉบับ การวิเคราะห์โครงสร้าง และการตรวจผล ไม่ได้เพิ่มโควต้า Gemini หรือเปลี่ยนคิว Render ให้เป็นที่เก็บถาวร

## การทำงาน

Apps Script ส่งไฟล์ `.docx` ให้ Python; Google Docs ถูก export เป็น Word ด้วยสิทธิ์ Google Drive ของเจ้าของ trigger Python อ่านข้อความ ลำดับย่อหน้า ตัวหนา รายการ และตาราง รวมถึงเซลล์รวม แล้วกำหนดรหัสให้แต่ละส่วน

Gemini ยังอ่านทั้งเอกสารและวิเคราะห์ความหมาย ลำดับหมวด หัวข้อซ้อน Module เวลา และ Workshop แต่ส่งกลับเป็นต้นไม้โครงสร้างที่อ้างอิงรหัสและช่วงข้อความ ไม่พิมพ์เนื้อหาหลักสูตรทั้งหมดใหม่ หนึ่งย่อหน้าสามารถถูกแบ่งเป็นหลายช่วงได้ ตารางต้นฉบับต้องถูกอ้างอิงเป็นตาราง

Python ตรวจรหัส ช่วงข้อความ ความซ้ำ และความครบ หาก AI ตกหล่นบางช่วง ระบบนำช่วงนั้นไปเก็บในหมวด “เนื้อหาต้นฉบับที่รอตรวจสอบ” และระบุ `review_required=true` หากอ้างอิงผิด ข้อมูลซ้ำ หรือเปลี่ยนตารางเป็นย่อหน้า จะหยุดงานพร้อมข้อผิดพลาด

ข้อเสนอแก้คำจะบันทึกข้อความเดิม ข้อเสนอ และเหตุผล ค่าเริ่มต้นยังใช้ข้อความเดิม ชื่อภาษาอังกฤษที่ AI เสนอใช้ตั้งชื่อไฟล์เท่านั้น ไม่เติมลงเนื้อหาหลักสูตรโดยอัตโนมัติ การตรวจความครบไม่ได้พิสูจน์ว่าการจัดหมวดถูกต้อง

## ผลลัพธ์และสถานะ

- งานที่ผ่านโดยไม่มีรายการตรวจสอบ: ต้นฉบับเปลี่ยนชื่อเป็น `[DONE]_...`
- งานที่ต้องตรวจเนื้อหาหรือโครงสร้าง: ต้นฉบับเปลี่ยนชื่อเป็น `[REVIEW]_...` และไม่ส่งซ้ำเอง
- ไฟล์ Word มีรายงานท้ายเอกสารเฉพาะเมื่อมีรายการต้องตรวจ
- โฟลเดอร์ Output มี `.review.json` คู่กับ Word ในโหมดใหม่ รายงานมีตำแหน่งข้อความ ข้อเสนอแก้คำ คำเตือน โมเดล และจำนวน token ที่ API ส่งกลับ
- การบันทึก Word และรายงานรองรับการกลับมาทำต่อหลัง Apps Script หยุดกลางทาง
- หน้าเว็บแจ้งให้ตรวจท้ายเอกสารเมื่อมี `review_required`

## การติดตั้งเมื่อพร้อมทดสอบออนไลน์

1. หยุด trigger ชั่วคราวและเก็บผลลัพธ์งานที่กำลังทำให้ครบก่อน deploy สำรองโค้ด Apps Script ที่ใช้งานจริงและค่า Environment ของ Render ล่าสุดไว้ส่วนตัวเพิ่มเติม
2. อัปเดต `app.py`, `job_store.py`, `generate_course_outline.py`, `reference_parser.py`, `reference_renderer.py`, `source_reader.py`, `templates/` และ `requirements.txt` ไปยัง repository ที่ Render ใช้อยู่
3. คง start command `uvicorn app:app --host 0.0.0.0 --port $PORT --workers 1` และค่า `BTOOLS_API_TOKEN`/Gemini เดิม
4. ตั้ง `BTOOLS_PARSER_MODE=references` และ `BTOOLS_APPLY_TYPO_EDITS=false` ค่าทั้งสองเป็นค่าเริ่มต้นอยู่แล้ว ไม่ต้องเปิด billing หรือเพิ่มบริการใหม่
5. อัปเดต Apps Script ด้วย `google_drive_automation/Code.gs` และเติมค่าตั้งส่วนตัวเดิมครบ 5 ค่า คง `USE_REFERENCE_SOURCE=true` ระบบใช้ OAuth token export Word จาก Drive ไม่ต้องเปิดเอกสารใน Drive เป็นสาธารณะ
6. ทดลองหนึ่งไฟล์ก่อน เปิด Word และรายงานตรวจสอบ จากนั้นค่อยเปิด trigger ทุก 5 นาทีตามเดิม
7. ก่อนเปลี่ยนใช้ทั้งหมด ควรทดสอบ AI จริงเทียบรุ่นเดิม 10–20 เอกสารที่หลากหลาย โดยตรวจเนื้อหา หัวข้อซ้อน ตาราง และ Workshop การทดสอบในเครื่องใช้ AI จำลอง จึงยังสรุปคะแนนคุณภาพการตีความหรืออัตราเร็วจริงไม่ได้

`GEMINI_MODELS` เปลี่ยนลำดับโมเดลได้โดยคั่นด้วยจุลภาค ค่าเริ่มต้นใช้รายชื่อเดิมของโปรเจค ตรวจสิทธิ์ใช้งานจริงของบัญชีใน AI Studio ก่อนเปลี่ยนชื่อโมเดล

หากตั้ง `BTOOLS_APPLY_TYPO_EDITS=true` ระบบจะใช้ข้อเสนอแก้คำเฉพาะช่วงที่อยู่ในตำแหน่งผลลัพธ์เดียว และแสดงรายการแก้พร้อมสถานะ REVIEW ยังควรตรวจความหมายของการแก้ทุกครั้ง

## ข้อจำกัดที่ระบุชัด

อ่านเนื้อหาหลักของเอกสาร ไม่ทำ OCR ภาพ ไม่อ่านเนื้อหาจาก altChunk ภายนอก และไม่คัดลอกข้อความใน header/footer/footnotes/endnotes เข้าหลักสูตร หากตรวจพบข้อความหรือวัตถุเหล่านี้จะแจ้ง REVIEW ตารางซ้อนเก็บข้อความไว้แต่ยังต้องตรวจรูปแบบ Track Changes อ่านข้อความเพิ่มและไม่รวมข้อความลบ

รองรับไฟล์ Word อัปโหลดไม่เกิน 20 MB และขนาดรวมเมื่อแตก ZIP ไม่เกิน 64 MB ส่วนการ export Google Docs ผ่าน Drive มีขีดจำกัดของบริการแยกต่างหาก ไฟล์ขนาดใหญ่ยังต้องทดสอบเวลา export จริง

คิวคงทำทีละงาน รับค้างได้ 2 งานและรับใหม่ 1 ไฟล์ต่อ trigger เช่นเดิม SQLite/ผลลัพธ์บน Render Free ยังอาจหายเมื่อ restart/redeploy จนกว่า Apps Script จะบันทึกลง Drive รุ่นนี้ยังไม่ได้เพิ่มคิวถาวร แคชข้ามงาน หรือการทำงานหลาย instance

## ย้อนกลับ

เปลี่ยน `BTOOLS_PARSER_MODE=legacy` เพื่อใช้ฟังก์ชัน AI เดิมอย่างรวดเร็ว วิธีนี้ยังใช้ตัวอ่านต้นฉบับและระบบงานรุ่นใหม่ จึงไม่ใช่การย้อนทั้งชุด

การย้อนไฟล์โปรเจคทั้งชุดให้ใช้ ZIP และ `restore.py` ใน `update_backups/pre_reference_parser_2026-10-09` ตามคู่มือในโฟลเดอร์นั้น มี manifest SHA-256 ของทุกไฟล์เดิมและการตรวจหลังคืนไฟล์

## การทดสอบในเครื่อง

```powershell
python btools_webapp/tests/test_reference_parser.py
python btools_webapp/tests/test_background_jobs.py
node google_drive_automation/tests/test_automation.js
```

ใช้ environment ที่มี dependency ตาม requirements และ httpx สำหรับ TestClient บน Windows ต้องอนุญาต loopback ภายในสำหรับ TestClient การทดสอบเหล่านี้ปิดการเรียก Gemini จริง อย่ารัน test discovery รวมสคริปต์เก่าที่มีการเรียก API จริง

อ้างอิงรูปแบบ JSON Schema: https://ai.google.dev/api/generate-content และการ export Word: https://developers.google.com/workspace/drive/api/guides/ref-export-formats
